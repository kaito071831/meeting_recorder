# meeting_recorder — オンライン会議 録音・文字起こし・議事録ツール

Microsoft Teams などブラウザで実施するオンライン会議を対象に、会議音声を
**録音 → 文字起こし → 議事録生成** するローカル Web アプリです。音声・文字起こしは
すべてローカルで処理されるため、機密情報を外部に送りません（議事録生成に Claude を
選んだ場合のみ、テキストのトランスクリプトが Anthropic API に送信されます。
Ollama を選べば完全ローカルで完結します）。

## 特長

- **クロスプラットフォーム**（Mac / Windows）。仮想オーディオデバイス
  （BlackHole / VB-Cable）等の OS 依存セットアップは不要。
- **音声取込はブラウザだけ**。会議はブラウザ版（Teams web / Zoom web / Google Meet）で
  実施し、画面共有 API でタブ音声（相手）＋マイク（自分）を取得します。
- **話者分離**（ソースベース）。マイク＝「自分」、タブ音声＝「相手・参加者」として
  2トラックを別々に録音・文字起こしします。
- **共有タブの画面を録画**（参照用）。共有した会議タブの映像＋タブ音声＋自分マイクを
  1本の `screen.webm` に合成して保存し、スライド・画面共有・参加者ビデオと全員の音声を
  後からそのまま見返せます（文字起こし・議事録には使いません）。
- **オフライン文字起こし**（`faster-whisper`、日本語、会議後の一括処理）。
- **議事録プロバイダを実行時に選択**（Claude `claude-opus-4-8` / ローカル Ollama）。
- 議事録は **要約 ＋ 決定事項 ＋ ToDo（担当・期限）**。タイムスタンプ付き全文も保存。

## 動作環境

- **ブラウザ: Chrome または Edge**（画面共有 API `getDisplayMedia` が必要）。
  Safari / Firefox は非対応です。
- Python 3.10 以上。
- パッケージ管理に **[uv](https://docs.astral.sh/uv/)** を使用します
  （未インストールなら `curl -LsSf https://astral.sh/uv/install.sh | sh`）。
- **ffmpeg のインストールは不要**です（faster-whisper が PyAV 同梱の ffmpeg
  ライブラリで WebM/Opus をデコードします）。

### 推奨スペック

文字起こし（faster-whisper）はローカル CPU（Mac は常に CPU、Windows は GPU があれば
高速化可）で動くため、マシンスペックが処理時間に直結します。以下は実測
（Apple M4 Max・16コア・64GB、`WHISPER_MODEL=large-v3-turbo` + バッチ推論）を基準にした目安です。

| | Claude で議事録生成 | Ollama で議事録生成もローカル（`gemma4:12b` 相当） |
| --- | --- | --- |
| CPU | 8コア/16スレッド以上（Intel Core i7 / Ryzen 7 以上、Apple M2/M3/M4系） | 同左 |
| RAM | 16GB 以上 | **32GB 推奨** |
| GPU | 不要（Windows は NVIDIA GPU があれば `WHISPER_DEVICE=cuda` で文字起こしを高速化可） | Windows: NVIDIA GPU（VRAM 12GB 以上推奨）／Mac: Apple Silicon なら Ollama が自動で GPU（Metal）を使用 |
| ディスク | SSD 空き 50GB 以上 | 同左 |

内訳（実測値）:

- 文字起こし（faster-whisper, large-v3-turbo, `cpu_threads=8` / `batch_size=8`）: 単一トラック処理時のピークRAM 約 6.2GB。1時間の音声（2トラック）を約6分で処理（旧 `large-v3` の逐次デコードでは同条件で約2時間）。
- ローカル議事録生成（Ollama, `gemma4:12b`）: ロード時のメモリ/VRAM 約 8.9GB。
- 文字起こしと議事録生成は逐次実行のため、アプリ全体のピークは両者の**大きい方**（約9GB）で見積もれば十分（合算不要）。
- 会議1時間あたりのディスク消費: 音声2トラックで約110MB、`screen.webm`（画面録画）込みで約830MB。

> 実測機はハイエンド（M4 Max）のため、処理時間はこれより低スペックな機種では伸びます。
> RAM・ディスクの目安はおおむね機種によらず妥当です。

### 推奨スペックに届かない場合の調整

- **文字起こしが遅い / CPU使用率が張り付く**: `WHISPER_CPU_THREADS` を実コア数以下に
  下げる（多すぎるとメモリ帯域律速でむしろ悪化することがあります）。それでも遅い場合は
  `WHISPER_MODEL=medium` や `small` にダウンシフトすると大幅に軽くなります（精度は低下）。
- **RAMが少ない（8〜16GB程度）**: `WHISPER_BATCH_SIZE` を `4` や `2` に下げるとメモリ
  消費を抑えられます（処理は多少遅くなります）。Ollama を使う場合は `gemma4:12b` より
  小さいモデル（7B前後など）に切り替えるか、議事録生成は Claude（クラウド）に任せて
  ローカルの負荷を文字起こしのみに絞るのがおすすめです。
- **Windows で GPU が無い / VRAM が足りない**: 文字起こしは `WHISPER_DEVICE=cpu` に
  固定して問題ありません（`auto` のままでも GPU が使えなければ自動で CPU 実行）。
  Ollama のローカル議事録生成は CPU 実行になり `gemma4:12b` クラスだと生成が遅くなるため、
  即時性が欲しい場合は Claude プロバイダを使う方が現実的です。
- **ディスク容量が厳しい**: `screen.webm`（画面録画）が容量の大半を占めるため、録画が
  不要なら保存後に削除する運用にすると音声・議事録のみで会議1時間あたり約110MBまで
  抑えられます。

## セットアップ

```bash
cd meeting_recorder
bash setup.sh
```

`setup.sh` は `uv sync` で `.venv` の作成と依存関係のインストールを行い、動作確認します
（`pyproject.toml` / `uv.lock` で管理）。`uv sync` を直接実行しても構いません。

続いて環境変数を設定します。

```bash
cp .env.local.example .env.local
# .env.local を編集し、ANTHROPIC_API_KEY を設定（または Ollama を起動）
```

- **Claude を使う場合**: `.env.local` に `ANTHROPIC_API_KEY` を設定します。
- **Ollama を使う場合**:
  1. [Ollama](https://ollama.com/) をインストールする（Mac: `brew install ollama`、
     Windows: 公式サイトからインストーラを取得）。
  2. 議事録生成用のモデルを取得する（動作確認済み: `gemma4:12b`。他のモデルでも可）。
     ```bash
     ollama pull gemma4:12b
     ```
  3. `ollama serve` でローカルサーバを起動しておく。UI に自動でモデル一覧が表示される。

## 起動

```bash
uv run uvicorn app:app --port 8000
```

Chrome / Edge で `http://localhost:8000` を開きます。

## 使い方

1. 会議タイトル・議事録プロバイダ（Claude / Ollama）を選ぶ。
2. 会議をブラウザ版で開いておく。
3. 「録音開始」を押す → 共有ダイアログで**会議タブを選び、「タブの音声も共有」に
   チェック**を入れる（**macOS では特に重要**。タブ音声のみ取得可能なため）。
4. マイクの許可を与える。両方のレベルメーターが振れていれば収音できています。
5. 会議終了後に「停止して処理」を押す。アップロード → 文字起こし → マージ →
   議事録生成の進捗が表示され、完了すると議事録が表示されます。
6. 「議事録をダウンロード」「全文をダウンロード」で Markdown を保存できます。
   録画がある会議では「録画をダウンロード」で `screen.webm`（共有タブの映像＋
   会議の全音声）を保存できます。

## 拡張機能版（Chrome / Edge）

Web版とは別に、**Chrome/Edge 拡張機能版**も同梱しています（`extension/`）。
`chrome.tabCapture` で会議タブの音声を直接取得するため、**共有ダイアログや
「タブの音声も共有」チェックが不要**になり、macOS でのチェック忘れ摩擦が消えます。
録音範囲・出力は Web版と同一（`mic.webm` / `tab.webm` / `screen.webm`）で、重い処理
（文字起こし・議事録生成）は同じローカルバックエンドが担います（拡張はもう一つの
フロントエンド）。

### 前提

- 先にバックエンドを起動しておきます: `uv run uvicorn app:app --port 8000`。
  拡張はこのローカル API（`http://localhost:8000`）へアップロード・SSE 受信します。

### インストール（未パッケージ拡張の読み込み）

1. Chrome は `chrome://extensions`、Edge は `edge://extensions` を開く。
2. 右上の **デベロッパーモード** を ON。
3. **「パッケージ化されていない拡張機能を読み込む」** で本リポジトリの `extension/`
   ディレクトリを指定する。
4. **初回のみ**: 拡張の「マイク許可ページ」を開いて許可する（popup 上部に未許可の
   案内が出ます。offscreen 録音からは許可プロンプトを出せないための一度きりの手順）。

### 使い方

1. 会議をブラウザ版（Teams web / Zoom web / Google Meet）で開き、**その会議タブを
   アクティブ**にする。
2. ツールバーの拡張アイコンをクリックして popup を開く。
3. 会議タイトル・議事録プロバイダ（Claude / Ollama）を設定し、**「録音開始」**。
   共有ダイアログは出ません。録音中も会議音声はスピーカーから聞こえ続けます。
4. 会議終了後に **「停止して処理」**。アップロード → 文字起こし → マージ →
   議事録生成の進捗が表示されます。popup を閉じても録音・処理は継続し、開き直すと
   進捗・結果が復元されます。
5. 完了後に議事録が表示され、「議事録DL」「全文DL」「録画DL」で保存できます。

### Web版との違い

| | Web版（`http://localhost:8000`） | 拡張機能版（`extension/`） |
| --- | --- | --- |
| 起動 | ブラウザで URL を開く | ツールバーの拡張アイコン |
| タブ音声取得 | `getDisplayMedia`（共有ダイアログ＋「タブの音声も共有」チェックが必要） | `tabCapture`（ダイアログ・チェック不要） |
| 対象タブ | 共有ダイアログで選択 | **アクティブな会議タブ**（開始前にアクティブにしておく） |
| 出力・処理 | 同一（`mic`/`tab`/`screen.webm`・同じバックエンド） | 同一 |

## 出力

会議ごとに `output/<YYYY-MM-DD>_<HHMM>_<タイトル>/` が作られ、以下が保存されます。

| ファイル | 内容 |
| --- | --- |
| `mic.webm` / `tab.webm` | 録音した2トラック（自分 / 相手・参加者） |
| `screen.webm` | 共有タブの映像＋会議の全音声（タブ音声＋自分マイク）。参照用の録画。文字起こしには未使用 |
| `transcript.md` | 時系列・話者ラベル付きの整形済みトランスクリプト |
| `transcript.json` | 生セグメント（両トラック）。別プロバイダでの議事録再生成用 |
| `minutes.md` | 議事録（要約 / 決定事項 / ToDo 表） |

> **注意（録画のファイルサイズ）**: `screen.webm` は動画のため音声トラックの
> 数十倍のサイズになり得ます（長時間会議では数百MB規模）。録画データは
> クライアント側でメモリに蓄積してからアップロードするため、長時間会議では
> ブラウザのメモリを消費します。

`output/`・`models/`・`.env.local` は `.gitignore` 済みです。

## 設定（`.env.local`）

| 変数 | 既定 | 説明 |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | （なし） | 設定すると Claude プロバイダが有効化。 |
| `CLAUDE_MODEL` | `claude-opus-4-8` | 使用する Claude モデル。 |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Ollama のエンドポイント。 |
| `OLLAMA_MODEL` | 一覧の先頭 | Ollama の既定モデル。 |
| `WHISPER_MODEL` | `large-v3-turbo` | 文字起こしモデル。`medium` / `large-v3` などに変更可。 |
| `WHISPER_DEVICE` | `auto` | `auto`（CUDA があれば GPU）/ `cpu` / `cuda`。 |
| `WHISPER_CPU_THREADS` | コア数（最大8） | CPU 推論時のスレッド数。 |
| `WHISPER_BATCH_SIZE` | `8` | バッチ推論（BatchedInferencePipeline）のバッチサイズ。 |

## パフォーマンスの注意

- **初回のモデルダウンロード**: 既定の `large-v3-turbo` は約 1.5GB を `models/` に一度だけ
  ダウンロードします（初回は時間がかかります）。
- **文字起こし速度**: CPU int8 では実時間かそれ以上かかることがあります。速度が
  必要な場合は `WHISPER_MODEL=medium` などにダウンシフトしてください。バッチ推論
  （`BatchedInferencePipeline`）により大幅高速化されており、`WHISPER_BATCH_SIZE` で調整可。
- **長時間会議**: クライアント側でチャンク化し、サーバ側で VAD フィルタを用いて
  メモリを抑えています。

## 制限事項・注意

- **ブラウザは Chrome / Edge 必須**。Safari / Firefox は画面共有 API 非対応。
- **macOS はタブ音声のみ**取得可能（システム音声は不可）。本用途では十分です。
  録画の映像も同様に共有タブが対象です（音声はタブ音声＋自分マイクを合成）。
- **録画のファイルサイズ・メモリ**: `screen.webm` は動画のため大きく（長時間会議で
  数百MB規模）、クライアント側でメモリに蓄積してからアップロードします。長時間の
  会議ではブラウザのメモリ消費に注意してください。録画動画にはタブ音声と自分マイクを
  合成した全音声が入ります（話者分離のため `mic.webm` / `tab.webm` は文字起こし用に
  別トラックで保存）。
- **マイクが無音／未接続**でも、タブ側（相手・参加者）のみのトランスクリプトを
  生成して処理を継続します。
- 話者分離はソースベース（自分 / 相手）です。タブ側の複数話者ダイアライゼーションは
  将来対応予定（pyannote.audio）。
